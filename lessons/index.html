Module 1

Mạng Máy Tính & Giao Thức Web (Networking, Protocols & Transport)

Hiểu bản chất cách dữ liệu di chuyển trên Internet, các tầng giao thức kết nối và tối ưu truyền tải dữ liệu Client-Server.

  • Bài 01 DNS Resolution & TCP/IP 3-Way Handshake sắp tới
    Cơ chế cache DNS 4 tầng (Browser, OS, Router, ISP Resolver), Recursive vs Authoritative NS, cơ chế bắt tay SYN → SYN-ACK → ACK và TCP Slow Start.
  • Bài 02 HTTPS & TLS Handshake (Asymmetric vs Symmetric, Certificate & CA) sắp tới
    Mã hóa bất đối xứng để trao đổi session key đối xứng, Chain of Trust, CA, và TLS 1.3 1-RTT Handshake.
  • Bài 03 HTTP Evolution: HTTP/1.1 vs HTTP/2 vs HTTP/3 (QUIC) sắp tới
    HOL Blocking ở HTTP/1.1, Multiplexing & HPACK ở HTTP/2, và QUIC trên nền UDP giải quyết HOL Blocking tầng TCP ở HTTP/3.
  • Bài 04 RESTful API Design & HTTP Semantics cho Frontend sắp tới
    HTTP Methods (GET, POST, PUT, PATCH, DELETE), tính Idempotency, ý nghĩa status codes 2xx/3xx/4xx/5xx và chuẩn hóa error payload.
  • Bài 05 Realtime Protocols: WebSocket vs Server-Sent Events (SSE) vs Polling sắp tới
    So sánh Short-polling, Long-polling, SSE (1 chiều server-to-client qua HTTP) và WebSocket (Full-duplex TCP song công).
  • Bài 06 Web Caching Internals: Cache-Control, ETag vs Last-Modified & 304 sắp tới
    Phân biệt max-age, no-cache vs no-store, stale-while-revalidate, cơ chế conditional requests với If-None-Match (ETag).
  • Bài 07 Same-Origin Policy (SOP) & CORS: Simple vs Preflight OPTIONS Requests sắp tới
    Định nghĩa Origin (Protocol + Host + Port), vì sao browser chặn cross-origin, khi nào kích hoạt Preflight OPTIONS request và cách cấu hình server headers.
🎯 Câu hỏi phỏng vấn thực tế — Module 1
  1. Khi bạn gõ URL https://google.com và nhấn Enter, chuyện gì xảy ra dưới góc nhìn mạng? → Trả lời theo luồng: DNS Cache lookup (Browser → OS → Router → ISP Resolver) → TCP 3-Way Handshake → TLS Handshake → HTTP Request/Response.
  2. Tại sao HTTP/2 nhanh hơn HTTP/1.1? HTTP/2 đã giải quyết triệt để HOL Blocking chưa? → HTTP/2 dùng Multiplexing truyền nhiều streams trên 1 TCP connection. Giải quyết HOL ở tầng ứng dụng, nhưng vẫn bị HOL ở tầng TCP khi rớt packet (cần HTTP/3 + QUIC).
  3. PUT và PATCH khác nhau như thế nào? Phương thức nào có tính Idempotent? → PUT: thay thế toàn bộ tài nguyên (Idempotent). PATCH: cập nhật một phần thuộc tính (thường non-idempotent).
  4. Một website thông báo chứng khoán nhảy giá liên tục nên dùng WebSocket hay SSE? Còn notification bell thì sao? → Bảng giá hoặc chat 2 chiều: WebSocket. Notification bell chỉ nhận tin từ server: SSE tiết kiệm tài nguyên, tự reconnect native.
  5. Lỗi CORS xảy ra ở phía client hay server? Ai là người chịu trách nhiệm fix? → Browser chặn vì chính sách SOP; Server là bên cấp phép qua headers Access-Control-Allow-Origin.

🎯 Câu hỏi phỏng vấn thực tế — Module 2
  1. JavaScript là single-threaded. Vậy tại sao nó không bị block khi xử lý hàng ngàn network requests cùng lúc? → JS Engine thực thi code single-thread trên Call Stack, nhưng I/O và timers được ủy thác cho Web APIs / libuv ở background thread pool, trả kết quả qua Callback Queue.
  2. Tại sao Google Chrome mở nhiều tab lại ngốn rất nhiều RAM? Đây là lỗi hay tính năng? → Tính năng Multi-Process & Site Isolation: mỗi tab chạy Renderer Process riêng để cô lập crash và phòng ngừa lỗi bảo mật Spectre, đổi lại tốn RAM hơn.
  3. Bộ dọn rác (GC) của V8 hoạt động như thế nào? Thế nào là Young vs Old Generation? → Giả thuyết Weak Generational: object mới tạo nằm ở Young Gen được dọn nhanh bằng Scavenger; sống sót qua 2 chu kỳ sẽ lên Old Gen và dọn bằng Mark-Sweep-Compact.

JavaScript Core, Ngữ Nghĩa Sâu & Bất Đồng Bộ (JS Runtime & Async Model)

Làm chủ Execution Context, Scope Chain, Closures, Prototype, `this` và luồng bất đồng bộ của Event Loop.

  • Bài 11 JS Deep Core: Execution Context, Scope Chain, Hoisting & Closures sắp tới
    Creation Phase vs Execution Phase, Lexical Environment, Temporal Dead Zone (TDZ) của let/const, và cơ chế giữ biến của Closures.
  • Bài 12 OOP trong JS: Prototype Chain, __proto__ vs prototype & 5 quy tắc this Binding sắp tới

  • Bài 13 Event Loop Sâu: Call Stack, Microtasks, Macrotasks & rAF ✓ sẵn sàng
    Thứ tự ưu tiên: Call Stack → Drain toàn bộ Microtasks (Promise, queueMicrotask) → Render (rAF) → 1 Macrotask (setTimeout, I/O).
  • Bài 14 Async Execution: Promise Internals, Async/Await Desugaring & Combinators sắp tới

🎯 Câu hỏi phỏng vấn thực tế — Module 3
  1. Closure là gì? Cho một ví dụ thực tế sử dụng Closure và một ví dụ Closure gây memory leak? → Closure là hàm ghi nhớ Lexical Scope nơi nó được tạo ra ngay cả khi hàm cha đã kết thúc thực thi. Dùng trong data privacy / memoization; gây leak khi giữ object dung lượng lớn không cần thiết.
  2. Giải thích cách từ khóa this được xác định trong JavaScript? Arrow function khác hàm thường thế nào? → this xác định tại runtime dựa trên CALL-SITE (cách hàm được gọi). Arrow function không có this riêng, nó kế thừa this tĩnh từ lexical scope bên ngoài.
  3. Đoạn code sau in ra thứ tự nào? 
    console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => console.log('3'));
queueMicrotask(() => console.log('4'));
console.log('5');
    → Thứ tự: 1 → 5 → 3 → 4 → 2 (Sync trước, Microtasks drain hết, Macrotask sau).

🎯 Câu hỏi phỏng vấn thực tế — Module 4
  1. Khác biệt giữa <script> thường, async và defer? → Thường: block HTML parsing. async: tải song song, chạy ngay khi xong (không giữ thứ tự). defer: tải song song, chạy sau khi DOM parse xong (giữ đúng thứ tự file).
  2. Layout Thrashing (Forced Synchronous Layout) là gì và làm sao để phòng tránh? → Xảy ra khi đọc thuộc tính layout (như offsetHeight) ngay sau khi ghi style trong vòng lặp. Khắc phục: gom tất cả thao tác đọc trước, ghi sau (Read-first, Write-later).
  3. Event Delegation là gì? Tại sao nên dùng khi render danh sách động 10,000 items? → Gắn 1 listener duy nhất lên thẻ cha dựa vào Event Bubbling thay vì gắn 10,000 listener lên từng phần tử con, giảm đáng kể Memory Heap và chi phí khởi tạo.

Lưu Trữ Trình Duyệt & Bảo Mật Web (Storage, Auth & Web Security)

Làm chủ các cơ chế lưu trữ client-side và nhận diện, phòng chống các lỗ hổng bảo mật Web phổ biến.

  • Bài 20 Browser Storage: Cookies (HttpOnly, SameSite) vs Web Storage vs IndexedDB sắp tới
    Dung lượng, vòng đời, bảo mật: Cookie (gửi theo request), localStorage (5-10MB synchronous), sessionStorage, IndexedDB (async NoSQL).
  • Bài 21 Web Authentication: Session Cookie vs JWT (Access/Refresh Token Rotation) sắp tới
    Cơ chế Session-based vs Token-based, Silent Token Refresh, phân tích vị trí lưu trữ an toàn: HttpOnly Cookie vs In-Memory + Refresh Token.
  • Bài 22 Cross-Site Scripting (XSS) & Kỹ thuật phòng chống (CSP, Sanitization, DOMPurify) sắp tới
    Phân loại Stored, Reflected, DOM XSS; nguy cơ đánh cắp token/session; phòng thủ đa lớp với Contextual Encoding, Content Security Policy (CSP) và DOMPurify.
  • Bài 23 CSRF, Clickjacking & Security Response Headers (HSTS, X-Frame-Options, SameSite) sắp tới
    Cơ chế mượn danh Cookie của CSRF; phòng chống bằng SameSite=Lax/Strict, Anti-CSRF Token; phòng thủ Clickjacking với X-Frame-Options & CSP frame-ancestors.
🎯 Câu hỏi phỏng vấn thực tế — Module 5
  1. JWT Auth Token nên lưu ở đâu an toàn nhất: localStorage hay HttpOnly Cookie? → localStorage dễ bị XSS đọc mất. HttpOnly Cookie chống được XSS đọc token nhưng có nguy cơ CSRF (cần kết hợp SameSite=Lax hoặc Anti-CSRF token).
  2. XSS khác CSRF như thế nào? → XSS: hacker tiêm và chạy mã JS trên trình duyệt người dùng (lấy cắp dữ liệu). CSRF: hacker lừa trình duyệt gửi request có kèm cookie hợp lệ mà người dùng không hề biết.
  3. Content Security Policy (CSP) là gì và làm sao để cấu hình chống XSS hiệu quả? → CSP là HTTP Header do server trả về chỉ định rõ nguồn tài nguyên (script, style, image) được phép tải và cấm thực thi eval() hay inline scripts nguy hiểm.

🎯 Câu hỏi phỏng vấn thực tế — Module 6
  1. 3 chỉ số Core Web Vitals của Google là gì? Chỉ số INP mới thay thế cho FID như thế nào? → LCP (tốc độ tải nội dung chính), INP (độ phản hồi tương tác xuyên suốt phiên dùng, đo worst-case latency thay vì chỉ first interaction như FID), CLS (độ ổn định thị giác).
  2. Phân biệt preload vs prefetch trong HTML? → preload: tải ngay tài nguyên bắt buộc cho trang hiện tại với độ ưu tiên cao. prefetch: tải trước tài nguyên có thể dùng cho trang tiếp theo khi mạng rảnh rỗi.
  3. Tree Shaking hoạt động như thế nào? Tại sao CommonJS khó Tree Shake hơn ES Modules? → Tree Shaking dựa vào cú pháp tĩnh (Static Analysis) của ESM (import/export) để xác định code thừa lúc build time. CommonJS dùng dynamic require() nên bundler không thể đoán trước lúc runtime.

🎯 Câu hỏi phỏng vấn thực tế — Module 7
  1. git rebase khác git merge như thế nào? Khi nào KHÔNG được rebase? → merge tạo commit gộp và giữ nguyên lịch sử phân nhánh. rebase tua lại và viết lại lịch sử commit lên đỉnh nhánh khác (tạo linear log). Quy tắc vàng: KHÔNG rebase trên branch public/shared.
  2. Bên trong thư mục .git, đối tượng Blob, Tree và Commit chứa những thông tin gì? → Blob: chỉ chứa nội dung nhị phân của file. Tree: chứa danh sách filename, permissions và SHA-1 của Blobs/sub-Trees (thư mục). Commit: chứa metadata (author, committer, message, timestamp, parent SHA) trỏ tới root Tree.
